# 方屿 Blockhaven

需要 Node.js 22。

安装：`npm ci`

本地启动：`npm run dev`，打开终端显示的地址。

Docker 启动：`docker compose up --build`，打开 http://localhost:8111。

## 昼夜、光照与建造

时间是一份 0–24 小时的世界状态（`WorldDocument.time`）。时间条或 `T`
键改变时刻；改变时刻**不会**触发光照重算，因为太阳高度只影响渲染与读数，
光照场只依赖方块。

光照本身是**派生数据**，从不写进存档：

- 天光从世界顶部向下传播，实体方块完全阻断，玻璃透过约 78%，树叶约 32%，
  因此玻璃房比树荫房亮，而两者都比露天暗。
- 火把是非实体光源，只沿相连的空格扩散，遇到实体墙和封住的门洞立即停止，
  不会照亮墙后的空间。
- 封闭房间的天光为 0，角色进入时读数与画面一致地变暗。

两个更新方式可在右侧「昼夜与光照」面板切换：

- **局部近似**：编辑后只重算编辑点周围 ±6 格，重新注入窗口边界的光，
  代价小，字段标记为近似。
- **完整传播**：每次编辑都从零重算整个世界，代价高但没有近似。

调度器每帧只给求解器约 3ms；连续放置方块时不会启动求解（避免每帧丢弃
正在进行的计算），停止编辑后再补齐。若某个求解是在旧世界版本上启动的
（例如火把刚被拆除），它的结果会被丢弃并重新排入队列，绝不会在画面上
显示已经拆除的火把。

## 存档

`WorldDocument` 只保存作者数据：方块、物品栏、角色位置、时刻与版本号。
材质颜色由材质表唯一提供；导入时会剥离任何逐方块的颜色/亮度字段，因此
画面曝光变化不会被当成材质本身保存。v1 存档可被自动升级读取。

## 测试

`npm test` 运行三组纯 Node 检查（无需浏览器）：

- `tests/lighting.test.ts` — 封闭空间、玻璃/树叶差异、时间曲线、迟到结果、
  局部与完整传播的代价与一致性、存档往返。
- `tests/runtime.test.ts` — 分帧调度、连续建造不阻塞、封闭门洞后的读数、
  火把拆除后的迟到计算、载入后重建。
- `tests/codec.test.ts` — v1 存档升级、时刻校验、剥除烘焙曝光。
